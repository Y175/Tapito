> 状态更新（2026-10-21）：项目当前选择开源方向；本页保留 2026-10-16 的历史方案和源码来源审计，不再代表当前产品目标，也未实施重新许可。当前许可及来源以根目录 LICENSE、THIRD_PARTY.md 与 README 为准。

## 已确认的产品方向

Tapito 目标是闭源商业产品，保留允许该分发方式的开源依赖及其声明。这是后续实现目标，**不是当前版本已经解除 GPL 义务的声明**。当前 LICENSE、第三方版权及源码头继续有效；本次没有更换许可证或修改运行代码。

工作流重构和许可证迁移是两个独立事项。UI、Agent、连接模块的技术解耦，不自动改变所复用代码的版权来源。独立原创模块可以另行评估许可，组合 App 仍需依据实际包含的代码判断。

## 后续实施顺序

1. 建立文件与依赖清单：原始来源、锁定版本、作者/权利人、许可证、本地修改、是否参与 App/扩展构建及分发。
2. 区分可直接保留的依赖、独立原创实现、待核实补丁、须替换或另行授权的实现。仅参考公开协议事实与复制、转译实现代码分别记录。
3. 保持既有连接和 Agent 接口，替换受限实现；以配对、屏幕流、触控、整段输入、取消、未知结果不重放和生命周期测试验证行为。
4. 单独处理不随产品编译的固件、测试参考及历史资料；其自身的分发许可继续保留，不能简单删除署名。
5. 完成最终构建依赖和源码来源复核后，再确定商业版许可文本与第三方声明；对外发行前由开源合规专业人员复核。

仅替换名字、删除 Git 历史、删除 GPL 文件头、将模块改为动态库或包，都不作为迁移完成的依据。当前阶段也不承诺已经找齐所有替换项。

## 完成标准

- 商业产品包含的全部源码及补丁有可追溯来源和支持该分发方式的授权。
- 原受 GPL 约束的实现已合法替换，或取得覆盖相应版权贡献的授权。
- 实际 App/扩展链接闭包与许可清单一致，开源依赖的声明随发行保留。
- 核心行为回归通过，不能为了许可迁移删除协议错误处理、身份隔离或动作回执。
- 新许可与 README 描述反映已完成事实，而不是预先宣称迁移成功。
